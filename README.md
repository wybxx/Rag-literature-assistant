#  文献检索助手（RAG Literature Assistant）

一个面向**研究生文献阅读**场景的 RAG（检索增强生成）问答系统：把一堆论文 PDF 丢进去，就能用自然语言提问，回答带**「文献名 + 页码 + 类型」的引用溯源**，并且能直接看到命中的**表格原图和插图**。

##  核心特性

**检索质量**

- **两阶段检索**：Bi-Encoder（bge-m3 双塔）宽召回 → Cross-Encoder（bge-reranker-v2-m3）精排，解决"短问题在长文本块上语义分数挤在一起、排序失效"的问题
- **混合检索 + RRF**：向量通道（语义）+ BM25 通道（关键词，jieba 分词）互补，用倒数排名融合（RRF）把跨通道共识的文档顶上来
- **查询改写与跨语言检索**：多轮对话消解指代；中文提问查英文文献时自动生成英文查询变体（Multi-Query Retrieval），解决 BM25 跨语言完全失效的问题
- **阈值标定**：不是拍脑袋定 0.3，而是实测相关 / 无关文档的分数分布（0.894 / 0.0006，跨语言 0.221~0.381）后取 **0.05**
- **召回配额**：表格 / 插图块常被正文和摘要挤出候选池 → 通道宽捞 + 类型保底配额，再按精排分数排序截断

**文献解析（面向论文的真实难点）**

- PyMuPDF 结构化抽取：**正文 + 表格（转 Markdown）+ 插图（渲染 PNG + 图注）**，全部带页码
- 表格识别三级策略：`lines` → `mixed`（横线定行 + 文本对齐定列，专治学术**三线表**）→ `text`（严格过滤，防把正文误判成表格）
- **两段式精提**：先用混合策略定位表格区域，再在区域内用 text 策略重提，解决单元格列错位
- **兜底矢量图形**：有些 PDF 把表格/图表"文字转曲"成矢量路径（`get_text` 读不到、`find_tables` 认不出）→ 用「线条密集区定位器」把整块区域渲染成图片入库，图注仍可检索

**问答体验**

- 摘要入库 + **全库汇总模式**：解决"这些文献的共性是什么"这类检索式 RAG 天然答不了的问题（答案不存在于任何单个块里）
- 流式输出、多轮对话、文献库浏览（逐篇查看解析出的表格与插图）
- **检索过程白盒化**：右栏展示每个候选块的分数、去留判定、配额补入情况，可信可解释
- 参数实时可调：Rerank / 阈值 / Top-K / 召回深度 / 混合检索 / 查询改写都能在界面上当场开关对比

**工程细节**

- **重建缓存**：解析结果按「文件哈希 + 抽取器版本号」缓存、摘要按全文哈希缓存 → 4 篇文献的重建从 **85s 降到 8s**
- 两处上游兼容补丁：修 `gradio_client` 与新版 pydantic 的 schema 解析冲突；修系统代理劫持 gradio「本地连通性自检」导致的启动崩溃（详见 `app.py` 顶部注释）
- 缺依赖时优雅降级（无 PyMuPDF → 纯文本；无 rank_bm25 → 退化为纯向量检索）

##  技术栈

| 模块 | 选型 |
|---|---|
| 编排框架 | LangChain |
| 向量数据库 | ChromaDB（本地持久化） |
| Embedding | 硅基流动 `BAAI/bge-m3` |
| Rerank | 硅基流动 `BAAI/bge-reranker-v2-m3`（Cross-Encoder） |
| 关键词检索 | rank_bm25 + jieba |
| 对话模型 | DeepSeek `deepseek-chat` |
| PDF 解析 | PyMuPDF（fitz） |
| 界面 | Gradio |

##  快速开始

```bash
# 1. 创建虚拟环境（推荐 Python 3.9+，本项目在 3.9.5 / Windows 上实测）
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate

# 2. 安装依赖（国内网络建议加镜像）
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/

# 3. 配置 API Key（需要两家：对话用 DeepSeek，向量化用硅基流动）
cp .env.example .env      # Windows: copy .env.example .env
# 编辑 .env 填自己的 key

# 4. 放入你的文献（支持 .pdf / .txt / .md / .docx）
#    仓库自带一篇示例文本，可直接替换

# 5. 重建知识库（解析 → 摘要 → 向量化入库）
python vector_store.py

# 6. 启动界面
python app.py             # 浏览器打开 http://127.0.0.1:7860

# 也可以纯命令行问答 / 查看检索报告
python rag_pipeline.py
```

> ⚠️ 请在**项目根目录**下运行（`config.py` 里的 `docs/`、`vector_db/` 等路径是相对当前工作目录的）。

## 项目结构

```
rag-doc-qa/
├── app.py                # Gradio 界面：智能问答 / 文献库 / 知识库管理 三个 Tab
├── rag_pipeline.py       # 编排层：改写 → 召回 → 融合 → 精排 → 过滤 → 路由 → 生成
├── hybrid_retriever.py   # 混合检索：向量 + BM25 双通道召回，RRF 融合，类型保底配额
├── rerank.py             # 精排：调用 Cross-Encoder 对候选逐对打分
├── vector_store.py       # 向量化入库（含分阶段计时）/ 加载 / 检索
├── loader.py             # 文档加载 + 抽取缓存 + 切块（只切正文，表格/插图整块保留）
├── pdf_extractor.py      # PDF 结构化抽取：正文 / 表格 Markdown / 插图 PNG / 矢量图形兜底
├── summarizer.py         # 文献摘要（Map-Reduce + 并行 + 哈希缓存）/ 汇总型问题识别
├── library.py            # 文献库聚合视图（清单、单篇详情、统计）
├── llm.py                # LLM 封装：生成 / 流式 / 查询改写 / 查询翻译 / 上下文拼装
├── utils.py              # 小工具：引用标签、类型标签、文本预览
├── config.py             # 全局配置（切块、召回、阈值、配额、缓存开关…）
├── EXPERIMENTS.md        # 实测数据与踩坑记录（调参依据都在这里）
├── requirements.txt
├── .env.example
└── docs/                 # 你的文献放这里（示例文本已验证可跑）
```

运行时自动生成（已 gitignore）：`vector_db/`（向量库）、`assets/`（抽出的表格/插图 PNG）、`summaries/`（摘要 Markdown）、`cache/`（抽取缓存）。

##  关键设计决策

| 决策 | 依据 |
|---|---|
| 切块 500 字 / 重叠 50 | 实测对比：100 字→1202 块（碎）、500 字→168 块、1500 字→58 块（粗），500/50 在"语义完整"与"检索精准"间最平衡 |
| 只切正文，表格与插图整块保留 | 表格被拦腰切断后没有表头，人和模型都读不懂 |
| Rerank 阈值 0.05（而非 0.3） | 实测同语言相关 0.894、跨语言相关 0.221~0.381、无关 0.0006；取 0.3 会把跨语言命中全部误杀 |
| 通道宽捞 + 类型保底配额 | 真实案例：结果表在向量通道排第 36 名进不了候选池，但精排给它 0.741 分——"不是不相关，是被同类内容淹没" |
| 先按分数排序再截断 Top-K | 否则保底补进来的高分块会被候选顺序无序截断挤掉 |
| 摘要入库而非提问时现算 | 现场生成意味着每次提问都要重读全部文献（几分钟）；入库后它就是普通块，走同一套召回链路，零额外成本 |
| 缓存键加入 `EXTRACTOR_VERSION` | 文件哈希只能感知输入变化，感知不了代码变化——改抽取逻辑时手动 +1，旧缓存整体失效，避免脏缓存 |

更多实测数据（分数分布、块数对比、85s→8s 的重建优化过程）见 [EXPERIMENTS.md](EXPERIMENTS.md)。

##  已知限制

- 汇总型问题依赖入库时生成的摘要质量：摘要漏掉的信息，全库模式下也答不出来
- 表格若在 PDF 里是**扫描图片**（非文字也非矢量），当前无 OCR，只能展示原图
- "文字转曲"的表格无法提取数据，只能作为图片入库 + 图注检索
- 阈值 / 配额等参数是针对当前文献集标定的，换领域语料建议重新测一遍分布
- `vector_db/` 未纳入版本控制，clone 后需自己跑一次 `python vector_store.py` 入库
